# Veyqa Voice 推广期内置语音服务

状态：用户已选择“短期凭证 + 音频直连百炼”，并批准开始工作及测试后发布；本文落实该选择，待用户审阅后进入实现。

## 用户结果与范围

- 新用户安装后无需注册、填写 Key；完成系统授权即可试用。
- 内置服务固定使用北京地域 `qwen-audio-3.0-asr-flash-streaming`，每设备每自然月免费 100 分钟，月份按 Asia/Shanghai 计算。
- 推广服务百炼月预算为 100 元，80 元提醒，达到预算停用内置服务。自带 Key 不受推广额度或推广停用影响。
- 老用户的 Key、所选模型、快捷键、词库及其他配置保留；已有自带 Key 的用户不自动切换到内置服务。
- 本轮不做登录、订阅、支付、在线网页试音，也不把长期 Key 打包进客户端。
- 完成现有固定签名及 Sparkle 更新工作，一并测试和发布；不修改系统安全策略。

## 已比较的方案

1. **采用：凭证服务 + 音频直连。** 香港服务器只做匿名设备登记、额度记录、短期凭证签发和服务状态，不经过音频与识别文本；保留当前百炼流式协议。
2. **不采用：流式音频中继。** 可可靠计量音频，但增加网络路径，不符合本轮优先保留直连速度的选择。
3. **保留：用户自带 Key 直连。** 用户可随时切换，继续使用已有千问、豆包及自定义供应商配置。

## 安全和额度边界

客户端拿到短期凭证后可直接调用百炼，所以 100 分钟是普通使用额度，不是防修改客户端的强安全边界。临时凭证有效期不是音频分钟额度，过期也不能未经验证就当作已连接任务会被中断。

服务器记录匿名设备身份、月用量、请求标识与时间，不接收音频、识别文本或用户自带 Key。设备身份使用随机值及设备认证秘密，保存在本机钥匙串，不采集硬件序列号。重新建立身份可能绕过设备额度，发布说明不得声称可以严格识别同一自然人或杜绝刷额度。

产品必须使用专用百炼 Key，只允许 3.0 Streaming 模型。该 Key 的权限和平台月预算必须在公开签发前实际核验，不复用权限不明的个人通用 Key。临时凭证继承其权限；原 Key 仅放服务端私有文件，不进 Git、构建包、网页、日志或命令输出。

百炼专用 Key 或专用业务空间设置月预算 100 元、80% 提醒、达预算停用。平台停用存在延迟，不宣称账单绝不会超过 100 元。服务端同时按已报告用量估算费用并设置停发开关，但客户端上报不能代替真实账单预算。公开上线前必须验证所选预算对象覆盖该 Key 签发的临时凭证调用；不能验证则不开放匿名签发。

## 凭证获取与首句体验

- 客户端增加独立的内置服务凭证管理器，暂定短期凭证有效期 300 秒，仅在主进程内存持有；不写 `.env` 或状态文件。
- 在选择内置服务、启动内置服务和一次听写结束后异步预取，合并同时发生的获取请求；空闲时不靠高频轮询持续刷新凭证。
- 只复用距离失效仍有安全余量的凭证；下一次连接前过期时刷新。正在运行的识别任务不因凭证刷新而重启。
- 缓存命中时不在快捷键路径申请凭证。缓存未命中时仍先启动录音，在现有有界音频缓冲内等待连接，不丢首句、不自动降级使用用户的私人 Key。
- 冷启动获取设置有限超时、退避和明确状态：正在连接、额度用尽、服务暂不可用、可使用自己的 Key；不阻塞主线程、不让健康检查把正常网络等待误判成死锁。
- 收到鉴权失败只在安全的会话初始化阶段清除旧缓存并重试一次；音频已发送后不自动重放整段，避免重复文字和计费。
- 不增加 AI 润色、音频转码或整段录完再上传的步骤。

## 设备用量与接口

- 所有公开接口仅 HTTPS、限制请求大小和超时；不接受客户端指定任意上游 URL、模型或 TTL。
- 匿名登记接口返回设备认证信息；后续状态、凭证及用量接口校验该设备秘密。凭证与设备认证信息不放 URL 查询参数。
- 设置页读取服务状态、选定模型和本月剩余额度，个人服务配置放在明确的“使用自己的 Key”入口下。
- 客户端根据发送的 PCM 时长记录会话用量；同一会话上报有唯一 ID，服务端幂等累计，拒绝负数、异常值、重复累加和跨设备操作。待补报记录不包含音频、文本或百炼凭证。
- 已知设备用完 6000 秒后拒绝继续签发并引导切换自带 Key；App 在免费额度耗尽时结束当前免费录音，保留已经识别的文字。断网、取消和异常退出分别测试，不以新 ID 重复上报。
- 服务端采用轻量 SQLite 事务，设备登记与签发做速率限制，支持全局停发，不宣称客户端版本号是安全认证。

## 香港服务器隔离部署

- 使用已授权 `kms-hk`，独立服务账户、目录和 systemd 单元，监听未占用的回环端口，复用现有 HTTPS 的独立路径。
- 服务端不引入 Docker、音频处理或模型依赖；限制内存、CPU、日志占用，服务失败不影响现有监控。
- 部署前记录已有服务状态，备份将修改的单个 Nginx 文件；配置测试通过后仅做平滑 reload，不重启监控。
- 不读取监控系统的凭证、订阅链接或私有业务日志。私钥不离开原位置。
- 服务端 Key 只通过已授权 SSH 的加密通道安装到私有目录，未就绪时内置服务保持关闭。

## 验收和发布门槛

1. **官方兼容性：** 实际生成短期凭证，用它连接 3.0 Streaming 并完成一次流式任务；验证所用地域与业务空间，不以 token 接口成功代替识别成功。
2. **速度：** 同一模型、同一音频对比长期 Key 直连与预取凭证直连，报告样本数、连接就绪、首个非空识别结果和结束后收尾耗时。缓存命中不得同步请求香港凭证接口；冷获取单独报告，不与热缓存混算。
3. **故障：** 测试过期、预取失败、401、429、断网、取消、重复请求、服务关闭和恢复；不丢首句、不重复输入、不因网络等待强制重启 App。
4. **额度：** 测试 6000 秒边界、月份切换、幂等上报、待补报、并发签发及预算停发；明确测试结果属于普通客户端额度，不伪装成强防刷。
5. **凭证：** 产品 Key 模型权限、平台预算、告警对象及通知方式已核验；日志、状态文件、Git diff、发布包扫描没有秘密。
6. **本机：** 配置备份后测试安装、首次授权、免填 Key 首次输入，以及老用户自带 Key 不变；连续输入三次、菜单栏与 Dock 打开设置正常。
7. **后台和更新：** 空闲无凭证轮询；按原口径测量 CPU/内存。修复更新窗口与健康监控误恢复问题，验证真实升级及权限保留。
8. **发布：** 所有必要测试通过后发布 GitHub 附件、签名 appcast、官网和 Homebrew；对照实际公开附件哈希、版本和服务状态，失败则不发布半成品。
