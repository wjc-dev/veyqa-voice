# 0.2.12 更新入口与验收

- 主清单：GitHub 仓库 `main/website/appcast.xml` 的原始文件地址。
- 备用清单：同一仓库 `update-feed` Release 的 `appcast.xml` 附件。
- 发布工作流逐字节镜像已签名清单后部署官网；仍需先发布并校验版本附件，再提交清单。
- Sparkle 会覆盖清单请求的 Accept，因此不使用需要定制 Accept 的 GitHub Contents API。
- 仅在主清单连接超时、DNS 或连接失败时重试一次；后台检查维持后台模式。下载包失败、用户取消、TLS 及签名错误不重试。
- 清单和包仍由同一 Sparkle Ed25519 公钥校验。固定 App 签名、每日检查周期和安装前忙闲保护不变。

测试覆盖一次重试、忙闲保护、后台模式、不同清单的隔离、证书与签名错误不重试，以及真实断连后的原生更新检查。公开推广凭证的分发约束继续遵循 0.2.10-maintainer.md。
