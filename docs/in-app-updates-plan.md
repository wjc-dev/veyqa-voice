# 应用内更新执行计划

范围：统一固定签名、Sparkle 应用内更新、官网 / GitHub / Homebrew 同步。本轮不开发账号、托管 API、额度或支付。

1. 固定 Sparkle 2.10.0 下载及 SHA-256；使用钥匙串中的更新签名密钥，仓库只保存公钥。
2. 添加主 App 原生 Sparkle 接入层、设置入口与私有请求通道；忙闲与未保存设置在启动安装前再次确认，暂停 Supervisor 后重启。
3. 更新构建与嵌套签名流程，所有公开包使用现有固定身份；测试不降级签名、不清空配置。
4. 添加请求 / 状态 / 失败 / 配置保护测试，编译原生接入层并验证打包依赖；运行完整回归。
5. 用隔离安装与测试更新源验证真实安装和重启，再更新本机；记录配置哈希、签名与权限，检查输入和入口。
6. 生成签名更新源，上传并校验附件，最后发布更新源、官网和 Homebrew。旧版用户需最后手动升级一次。

若无法安全通过实际安装或签名验证，保留现有安装并停止发布，报告确切未通过项。异机实测需要额外设备，不以本机结果代替。
