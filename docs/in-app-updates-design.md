# Veyqa Voice 应用内更新

状态：待设计复核；用户已批准一键更新方向与上线、本机更新目标。本文仅用于开发维护，不加入面向用户的 README。

## 目标

首次通过 DMG 或 Homebrew 安装后，用户可在应用内检查新版、查看简短说明、下载并安装，最后重新打开应用。更新不打断听写，不修改 API 凭证、快捷键、词库和其他用户配置。

采用 Sparkle 2，不自行实现下载包替换器。第一版更新完整 App 包，不做差分包、自定义更新窗口或静默安装。

## 当前接入条件

- 主程序是 PyInstaller 打包的 Python / PyObjC AppKit 应用，负责快捷键、听写和 Dock / 菜单栏。
- SwiftUI 设置是按需启动的独立进程，关闭设置后可退出。因此更新器不能依赖设置窗口一直存在。
- Supervisor 会恢复意外退出的主程序。更新时必须显式暂停它，避免新旧版本同时启动。
- 当前发布版是 0.2.8 / 217；本机使用固定证书签名，公开包为 ad-hoc 签名。
- 用户尚未购买 Apple Developer Program；本轮不改变此选择，不申请付费账号，不修改系统安全策略。

## 方案比较

1. **Sparkle 2 + 原生接入层（采用）**：使用成熟的签名校验、更新界面和安装器；本项目只负责听写协调、入口、渠道和发布。
2. **自建下载与替换器**：自由度高，但需要自行维护权限、安装事务、符号链接、失败恢复和安全校验；不采用。
3. **按钮打开官网或运行 Homebrew**：实现简单，但不具备用户需要的一键安装与重启体验；保留为备用更新方式。

## 用户交互

- 设置页的“应用”区域显示版本与“检查更新”，不新增独立 Tab。
- App 菜单提供“检查更新…”入口；菜单栏图标继续维持打开设置的现有交互。
- 使用 Sparkle 原生更新窗口展示版本、简短说明、下载进度和安装 / 重新打开操作。
- 默认每天检查一次新版；用户可以关闭自动检查。默认不自动下载、不静默安装，不发送系统画像。
- 新手配置未完成时不弹出后台更新提示；手动检查仍有明确结果。
- 正在听写、识别收尾或写入文字时，延后更新提示与重启。用户不必重启 App 才能继续输入。
- 从 DMG 只读卷或临时位置运行时，提示先拖入“应用程序”，不自动复制到任意目录。

## 运行时结构

### 常驻更新控制器

主 App 拥有唯一更新控制器，与 AppKit 主线程同生命周期。原生接入层负责持有 Sparkle 对象和实现其委托，避免在 Python 中复制 Sparkle 的调度和安装逻辑。

Python 侧只暴露当前忙闲状态、首次设置状态，以及开始更新前的清理通知。设置进程通过现有私有数据目录中的命令通道请求主 App 检查更新，不直接替换主 App。请求有唯一标识、去重和过期检查，不能包含任意 URL 或可执行路径。

原生接入层使用 Swift / Objective-C 可见接口；框架随主 App 打包，不要求用户安装 Swift、Python、Homebrew 或其他运行时。

### 听写与退出协调

- 主线程读取受保护的会话状态，不能只看动画图标判断空闲。
- 安装重启前再次检查录音、识别、文字写入、麦克风测试和设置保存状态。
- 等待期间继续允许当前听写完整结束；进入安装事务后阻止开启新的听写。
- 设置存在未保存修改时，要求用户先保存或取消修改；不得关闭窗口丢弃草稿。
- 只在确实开始安装时暂停 Supervisor，并正常结束本 App 拥有的设置进程、录音子进程和网络任务。
- 安装失败或用户取消时恢复正常运行和 Supervisor 状态；新版启动成功后恢复用户原来的登录启动偏好。
- 失败提示提供重试和官网入口，不清空 Key、重置权限或要求删除配置。

## 更新渠道与签名

### 两条发布渠道

- **公开渠道**：官网 / Homebrew 用户使用公开 App 包和公开 appcast。
- **本机固定签名渠道**：本机继续使用现有固定证书签名，获取同样代码的固定签名更新包；使用独立 appcast。公开渠道不得替换本机固定签名包。
- 渠道由签名封装中的构建元数据指定，不由远端列表或用户可编辑的 API 配置切换。
- 固定签名包不包含本机配置、私钥或用户数据；若在 GitHub 托管该更新包，发布内容仅为可分发 App 和公开证书信息。
- 两个渠道各自验证更新包的签名与版本，不因为另一个渠道的版本更高而跨渠道安装。

### 校验与密钥

- 固定 Sparkle 版本和下载校验值，构建保留其许可证及原始安全资源。
- Sparkle Ed25519 私钥存放登录钥匙串；仓库和 App 只包含公钥，不导出私钥到发布目录、日志或 CI。
- 更新包用 Ed25519 签名，appcast 使用 HTTPS，并启用解压前校验；使用所选 Sparkle 版本支持的已签名更新源机制。
- 发布工具验证 appcast 中的版本、渠道、长度、签名和下载目标，拒绝缺失签名、旧版本和不匹配包。
- 更新源只发布官方 GitHub Release 中已上传并完成校验的文件，最后再上线更新源，避免用户获取半发布版本。
- Sparkle 更新签名不替代 Apple Developer ID 或公证；本轮不宣称公开版已经公证，也不承诺公开 ad-hoc 包在所有 Mac 升级后保留 TCC 权限。
- 不执行清除 quarantine、重置 TCC、修改信任策略或绕过公司安全软件的命令。

## 安装失败与恢复

使用 Sparkle 安装器的事务与失败处理，不在 App 内另写覆盖脚本。下载失败、取消、校验失败不得更改当前安装。安装阶段失败必须验证旧版本仍可启动。

安装失败恢复与“新版成功安装但自身有功能缺陷”分开验收：本轮保存可用于恢复的旧版本及开发回退步骤，不声称 Sparkle 自动诊断所有启动后故障。Supervisor 仍负责已有的进程 / 心跳恢复能力。

## 构建与发布

- 下一版使用递增营销版本与构建号，保证两个渠道版本一致。
- 构建脚本嵌入 Sparkle 及原生接入层，按从内到外顺序签名；验证 XPC / Helper / 框架和外层 App 的完整签名。
- 发布工具从实际包读取版本与渠道，生成并签名对应 appcast，避免重复手工维护版本 / URL / 长度。
- GitHub Release、官网 DMG、README 更新说明和 Homebrew 配方同步；Homebrew 仅在真实内置更新通过验收后标记 `auto_updates true`。
- 旧版 0.2.8 不含更新器，已有用户需最后手动升级一次，之后才可应用内更新。
- 本机先备份配置并记录文件哈希，安装固定签名新版，再验证 Key / 配置及现有权限保留。

## 验收门槛

1. 单元测试：忙闲协调、请求去重 / 过期、错误与取消恢复、渠道隔离、版本比较、配置不变。
2. 原生测试：Sparkle 能实际加载，检查按钮可用，最新版本 / 网络失败均有正常结果。
3. 包校验：两个渠道包完整签名，依赖齐全，无私钥、Key、配置或运行记录。
4. 端到端：在隔离目录和测试更新源中，从包含更新器的旧构建实际下载、校验、安装到较新构建并重新打开；验证版本变化，而不只验证弹窗。
5. 故障用例：损坏包 / 错误签名 / 离线 / 用户取消 / 安装目标不可写；当前安装和配置保持可恢复。
6. 听写与设置：更新等待时完成听写，未保存草稿有明确处理，更新后连续三次输入、菜单栏及 Dock 入口正常。
7. 本机固定签名：签名身份不变，Key 和配置哈希一致，实际读取当前权限状态；如仍需系统确认如实报告，不自动重置权限。
8. 性能：更新空闲不增加高频轮询；按同样方法测量空闲 CPU / 内存，并与当前版本比较。
9. 发布：公开附件 SHA-256 与本地一致，HTTPS 更新源可获取且验签成功，官网和 Homebrew 实际下载一致。

全部必要验收通过后发布；如钥匙串、安全软件或系统权限需要人工确认，暂停对应步骤并给出确切操作，不反复触发弹窗。
